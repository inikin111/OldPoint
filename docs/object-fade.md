# 家具与物体模型统一消隐

同一物体的不同绘制表示共享透明度与推进速度。当前使用像素消隐，不使用整物体透明混合通道。

## 当前行为

同一个 `IsoObject` 的主体、overlay、attached parts、模型包和贴图回退表示，以及独立刚体模型子网格，读取一份捕获时推进的对象透明度。模型数量和绘制次数不会加快变化速度。独立模型不再在绘制时重新计算一套目标。

| 自由相机遮挡判定命中 | 目标不透明度 |
| --- | ---: |
| 同房普通家具遮挡角色 | 0.66 |
| 不同房家具遮挡当前房间，`isCanSee` 为真 | 0.25 |
| 不同房家具遮挡当前房间，`isCanSee` 为假 | 0 |
| 遮挡解除 | 1 |

使用原版透明度等级，但遮挡条件仍是既有自由相机几何判定，不能声称与原版固定视角筛选完全等价。门窗、室外附近物体等保留原有目标等级，接入同一对象过渡。与结构墙绑定的独立附属贴图继续使用其自身切墙规则，不把整个墙对象变成家具消隐。

`ObjectOpacity` 采用真实捕获时间：不透明度每秒最多降低 1；室内每秒最多恢复 7，室外每秒最多恢复 3.5。恢复/淡出比例参考原版普通对象，绝对秒数是本项目统一参数，不是声称原版某条路径的精确时长。单次时间间隔最多计 0.25 秒，避免长时间停顿后的一次性跳变。

## 实现

- `OpeningFade.capture` 仍缓存几何目标，给需要整体消隐的每个表示记录所属对象。保留同对象中不单独遮挡角色的其他表示，以便整个对象统一变化。
- `ObjectFade.capture` 在 `Interior.capture` 中每次运行；即使几何目标仍来自缓存，透明度也会推进。按对象合并最强目标，再让全部表示共享当前值。
- 目标消失后保留上一组源绑定，直至该对象恢复完全不透明后移除，避免退出遮挡时突然恢复。场景、玩家或楼层上下文切换会清掉旧状态，已发布帧快照不被后续推进修改。
- `OpeningModels` 只读取快照中的对象值，写给该对象的全部刚体子网格。
- `OcclusionShaders` 统一使用 Viewpoint 的 `fadeNoise()` 和 `noise >= opacity` 覆盖率约定，与刚体模型一致。没有引入整物体 alpha 混合。

墙体轮廓仍直接切换；屋顶、上层物体的结构性提前剔除仍保留。台面独立掉落物跟随支撑物透明度尚未新增，共享对象状态不包含这种跨对象关系。原版特殊透明分支尚未全部覆盖。

## 验证

`scripts/test.ps1 -Suite Occlusion` 执行实际对象透明度捕获与消费代码，覆盖不同表示共享状态、缓存命中继续推进、退出恢复、帧快照、回收、上下文隔离和帧率差异。见[测试说明](../java/tests/README.md)。

离线验证不替代游戏内观感验收。台面掉落物跟随支撑物透明度、原版真透明混合和 Iris 的专项适配不属于当前共享状态约定。
