# 墙体遮挡

墙体遮挡分为目标空间选择、连续投影选墙、端点轮廓和 GPU 裁剪四个阶段。房间、可见性、窥视和对象存在条件由捕获端提供；几何投影不替代游戏语义。

```text
房间与室外关注目标 → 墙面或建筑体投影 → 与有效目标面积求交
                 → 主墙排序与容量限制 → 实体邻墙和端点轮廓 → 规则上传与裁剪
```

## 连续投影

`CutawayProjection` 对完整单位墙面建立视锥边平面，与玩家所在楼层的目标矩形裁剪求交。接触边或点不算面积命中。角色保护区为连续的 0.6×0.6 格区域，其他目标按完整格子面积处理。

相机采用齐次表示：`w=0` 为朝向正交相机的方向，`w=1` 为有限透视相机的位置。两者共用平面约束和多边形裁剪。原版参考正交输入是 `(3,3,H,0)`，`H=2.4494896`；北墙、西墙的正面积覆盖可与游戏字节码中的六格模板对照。实际俯视使用 Viewpoint 的有限透视相机，覆盖不必与原版固定正交视角相同。

建筑使用六面体投影，并按真实房间矩形细化，保留庭院和凹形空隙。相机与墙顶等高或低于墙顶时，直接以平面约束裁剪到有限目标区域，避免发散顶点。查询缓冲为线程局部，不为每个目标分配新的多边形数组。

## 端点轮廓

`WallContour` 在每个交点使用朝向实际相机的视线，独立决定两端圆弧：

1. 与未选中的共线实体延续墙相接时形成过渡。
2. 与未选中的垂直支墙相接，且两臂投影位于交线同侧、支墙在后方时形成过渡。
3. 朝向相机、分处投影交线两侧的转角，保留画面左侧切低臂的过渡，但要求另一端存在已选中的共线实体延续墙。
4. 其余端点保持矮墙根；缺少延续墙本身不要求高端头。

第三条是依据原版非对称表现采用的视觉策略，不能解释为普遍遮挡定理。每个端点独立计算，因此允许双端圆弧；`NativeWallContour` 仅作为原版单列选择的参考实现。

在交点 V，a 为切低墙向外的单位水平切向，b 为支墙切向，h 为交点朝向相机的水平单位向量，屏幕右侧方向为 `r=(h_y,-h_x)`。记 `u_a=r·a`、`u_b=r·b`、`d_a=h·a`、`d_b=h·b`，同侧后方条件为：

```text
u_a * u_b > 0
d_b * abs(u_a) < d_a * abs(u_b)
```

前方左侧策略要求 `u_a < 0 < u_b`、`d_a > 0`、`d_b > 0`，再检查切低臂另一端的已选中实体延续墙。透视相机逐交点计算 h，正交相机共享方向。

墙体按选中状态直接切到最终轮廓，取消选中即恢复。主墙强度固定为 1，不保存 0.22 秒渐变历史；保留区为 10% 矮墙和端点圆弧，使用原材质与既有着色器过滤。门窗及家具的对象淡出独立推进。

## 对象身份与组合面

语义选墙位、对象的实际遮罩范围、最终面轮廓是不同信息。`WallTopology` 捕获实体邻墙和已上传主墙，按原版墙对象、门窗和车库门回退规则判定墙存在，并排除 WallSE；缺失格子视为无墙。

只有北、西面属于同一个非空真实墙对象时，才允许未选中的面继承组合遮罩。它还要求相机方向上的实体直线延续墙正在裁剪。右向交接保留远端过渡，左向交接使用普通轮廓。

伴随面标记 `maskOnly`，不进入主墙选择集合，不反馈邻墙选中位，也不触发门窗选墙查询；强度取同对象选中面和延续墙的较小值。它只占用剩余规则容量，不挤掉主墙。

## 限制与验证

- 面积阈值为 `1e-9`，用于抑制浮点接触噪声。
- 连续投影仍产生离散墙格标志，格边界处可以发生切换。
- 相机位于当前楼层地面及以下时返回空覆盖。
- 室内目标区域受玩家周围 ±32 格范围约束，候选最多 256 条，上传最多 128 条墙规则。
- 当前以平面墙和建筑体为基础，未补切口封面、厚度或描边。
- 原版全部房间、围栏、门窗特殊行和遮罩分支的等价性，以及地形起伏、实际阴影和所有光影包，需要分别验证。

行为测试覆盖室内外选择、投影退化、轮廓、对象身份和容量；原版字节码、独立屏幕投影与轮廓模型对照通过 `scripts/test.ps1 -Suite Reference` 按需运行。运行方式见[开发命令](../scripts/README.md)。这些检查不证明实际游戏画面或帧时间。

“墙体裁剪调试着色”选项中，绿色标记匹配的墙规则，红色标记本应裁掉而暂留观察的片元。
